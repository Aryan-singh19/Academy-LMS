@ cs402 | CS-402 | Analysis & Design of Algorithms | Asymptotic analysis, divide and conquer, greedy, dynamic programming, backtracking, branch and bound and NP-completeness.
# Algorithm Analysis & Divide and Conquer
- Asymptotic Notations | Notations compare growth rates independent of machines. | Big-O = asymptotic upper bound, f(n) ≤ c·g(n) for large n | Big-Omega = asymptotic lower bound on growth | Big-Theta = tight bound when both upper and lower bounds hold
- Recurrences & Master Theorem | Recursive algorithms are analysed through recurrence relations. | Master Theorem = solves T(n) = aT(n/b) + f(n) by comparing f(n) with n^(log_b a) | Recursion Tree = expands a recurrence level by level to sum the cost | Substitution Method = guess a bound and prove it by induction
- Binary Search, Merge Sort & Quick Sort | Divide and conquer splits, solves and combines subproblems. | Divide and Conquer = break into subproblems, solve recursively, combine results | Merge Sort Recurrence = T(n) = 2T(n/2) + n, giving O(n log n) | Randomised Quick Sort = random pivot gives expected O(n log n)
- Strassen's Matrix Multiplication | Clever splitting reduces the number of multiplications. | Strassen's Algorithm = multiplies 2×2 blocks using 7 multiplications instead of 8 | Strassen Complexity = O(n^2.81) versus O(n³) for the naive method | Max-Min Problem = finds maximum and minimum with about 3n/2 − 2 comparisons
# Greedy Method
- Greedy Strategy | Greedy algorithms make the locally best choice at each step. | Greedy Choice Property = a global optimum can be reached by local optimal choices | Optimal Substructure = optimal solution contains optimal solutions to subproblems | Feasible Solution = solution that satisfies all problem constraints
- Fractional Knapsack & Job Sequencing | Classic greedy problems sort by a ratio or profit. | Fractional Knapsack = take items in decreasing profit/weight ratio; fractions allowed | Job Sequencing with Deadlines = schedule highest-profit jobs in latest free slot before deadline | Optimal Merge Pattern = repeatedly merge the two smallest files
- Huffman Coding | Variable-length prefix codes compress data optimally. | Huffman Coding = builds a binary tree by merging two least frequent symbols | Prefix Code = no codeword is a prefix of another | Average Code Length = Σ frequency × codeword length
- Minimum Spanning Trees & Dijkstra | Greedy graph algorithms connect or route at minimum cost. | Kruskal's Algorithm = sorts edges and adds those not forming a cycle; O(E log E) | Prim's Algorithm = grows the tree by the cheapest edge leaving it | Dijkstra's Algorithm = greedy shortest paths for non-negative edge weights
# Dynamic Programming
- Principles of Dynamic Programming | DP solves overlapping subproblems once and reuses answers. | Overlapping Subproblems = the same subproblems recur many times | Memoization = top-down DP storing results of recursive calls | Tabulation = bottom-up DP filling a table iteratively
- 0/1 Knapsack & Multistage Graphs | DP handles problems where greedy fails. | 0/1 Knapsack = items taken whole or not at all; solved with a profit table | Multistage Graph = shortest path through stages solved backward or forward | Reliability Design = maximise system reliability under a cost constraint
- Longest Common Subsequence & Matrix Chain | Sequence and ordering problems are classic DP examples. | LCS = longest subsequence common to two strings, O(mn) table | Matrix Chain Multiplication = finds parenthesisation minimising scalar multiplications | Optimal BST = BST minimising expected search cost from key probabilities
- All-Pairs Shortest Paths & TSP | DP solves graph problems across all vertex pairs. | Floyd-Warshall = all-pairs shortest paths in O(n³) | Bellman-Ford = single-source shortest paths allowing negative edges | Travelling Salesman by DP = Held-Karp algorithm in O(n² 2^n)
# Backtracking & Branch and Bound
- Backtracking Method | Backtracking builds solutions incrementally and abandons dead ends. | State Space Tree = tree of all partial solutions explored by the algorithm | Bounding Function = test that prunes nodes that cannot lead to a solution | Backtracking = depth-first search with pruning of infeasible branches
- N-Queens & Graph Colouring | Constraint problems are classic backtracking examples. | N-Queens Problem = place N queens so none attack each other | m-Colouring Problem = colour a graph with m colours so adjacent vertices differ | Hamiltonian Cycle Search = backtracking over vertex orders
- Sum of Subsets | Find subsets of numbers adding to a target. | Sum of Subsets = choose elements whose sum equals a given value M | Promising Node = node whose partial sum can still reach M | Pruning Condition = stop when partial sum exceeds M or remaining sum is too small
- Branch and Bound | B&B explores the state space using bounds and a live-node list. | Branch and Bound = breadth-like search using cost bounds to prune | LC Search = least-cost search selecting the live node with smallest estimated cost | FIFO Branch and Bound = live nodes explored in queue order
# Advanced Topics & Complexity Classes
- Tree & Graph Traversal Techniques | Traversals underpin many advanced algorithms. | Articulation Point = vertex whose removal disconnects the graph | Biconnected Component = maximal subgraph with no articulation point | DFS Tree = tree formed by edges used during depth-first search
- String Matching Algorithms | Efficient algorithms locate patterns in text. | KMP Algorithm = uses a prefix function to avoid rechecking; O(n + m) | Rabin-Karp = rolling hash compares pattern and text windows | Naive Matching = checks every shift; O(nm)
- P, NP & NP-Complete | Complexity classes separate tractable from likely intractable problems. | Class P = problems solvable in polynomial time | Class NP = problems whose solutions are verifiable in polynomial time | NP-Complete = problems in NP to which every NP problem reduces
- NP-Hard Problems & Approximation | Hard problems are tackled by reductions and approximations. | NP-Hard = at least as hard as every NP problem, not necessarily in NP | Cook's Theorem = SAT is NP-complete | Approximation Algorithm = gives a near-optimal solution with a proven ratio

@ cs403 | CS-403 | Software Engineering | Process models, requirements, design, testing, project estimation, quality and maintenance.
# Software Process Models
- Software Engineering Fundamentals | Software engineering applies disciplined methods to build reliable software. | Software Crisis = projects running late, over budget and unreliable | Software Process = framework of activities for building software | Software Characteristics = software is developed, not manufactured, and does not wear out
- Waterfall & V-Model | Linear models complete each phase before the next. | Waterfall Model = sequential phases from requirements to maintenance | V-Model = each development phase paired with a testing phase | Phase Containment = catching errors in the phase that created them
- Prototyping, Spiral & Incremental Models | Iterative models reduce risk and gather feedback. | Prototyping Model = build a quick prototype to clarify requirements | Spiral Model = risk-driven iterations through four quadrants | Incremental Model = deliver the product in usable increments
- Agile Methodology | Agile values working software and responding to change. | Agile Manifesto = individuals, working software, collaboration and responding to change | Scrum Sprint = fixed time-box, usually 2-4 weeks, producing a shippable increment | Extreme Programming = practices such as pair programming and test-driven development
# Requirements Engineering
- Requirement Elicitation | Requirements are gathered from stakeholders. | Functional Requirement = what the system must do | Non-functional Requirement = quality constraints such as performance and security | Elicitation Techniques = interviews, questionnaires, brainstorming and observation
- SRS Document | The SRS records agreed requirements precisely. | SRS = software requirements specification document | Characteristics of SRS = correct, unambiguous, complete, consistent and verifiable | IEEE 830 = standard template for SRS documents
- Analysis Modelling | Models describe data and behaviour of the system. | Data Flow Diagram = shows processes, data stores and flows between them | Data Dictionary = definitions of all data elements used in models | ER Diagram = models entities, attributes and relationships
- Feasibility Study & Validation | Teams check whether the project is worth doing and requirements are right. | Feasibility Study = technical, economic and operational viability check | Requirements Validation = reviews and prototyping to confirm requirements | Requirements Traceability = linking requirements to design, code and tests
# Software Design
- Design Concepts | Good design manages complexity through abstraction. | Abstraction = hiding details to focus on essentials | Modularity = dividing software into separately named modules | Information Hiding = modules conceal internal details from others
- Coupling & Cohesion | Quality of modular design is measured by dependency and focus. | Cohesion = how closely the functions within one module belong together | Coupling = degree of interdependence between modules | Ideal Design = high functional cohesion with low data coupling
- Architectural & Structured Design | Architecture fixes the overall structure of components. | Structure Chart = hierarchy of modules and their calls | Transform Analysis = maps a DFD with input, process and output flows to a structure chart | Architectural Style = pattern such as layered, client-server or pipe-and-filter
- User Interface Design | UI design focuses on usability. | Golden Rules = place user in control, reduce memory load, keep interface consistent | Usability = ease with which users achieve goals | Heuristic Evaluation = expert review against usability principles
# Software Testing
- Testing Fundamentals | Testing finds defects before users do. | Verification = are we building the product right | Validation = are we building the right product | Test Case = inputs, steps and expected result for checking a feature
- White-box Testing | Tests derived from internal code structure. | Cyclomatic Complexity = V(G) = E − N + 2; number of independent paths | Basis Path Testing = tests covering each independent path | Statement Coverage = every statement executed at least once
- Black-box Testing | Tests derived from specifications without seeing code. | Equivalence Partitioning = divide inputs into classes expected to behave alike | Boundary Value Analysis = test at and around the edges of input ranges | Cause-Effect Graphing = derive tests from logical relationships of inputs and outputs
- Levels of Testing | Testing proceeds from units to the whole system. | Unit Testing = testing individual modules in isolation | Integration Testing = testing interfaces between combined modules | Regression Testing = re-running tests after changes to catch new defects
# Project Management, Quality & Maintenance
- Software Metrics & Estimation | Size and effort are estimated to plan projects. | LOC = lines of code size metric | Function Point = size measure from inputs, outputs, inquiries, files and interfaces | Basic COCOMO = Effort = a × (KLOC)^b person-months
- Scheduling & Risk Management | Plans track tasks and anticipate problems. | Gantt Chart = bar chart showing task durations over time | Critical Path = longest path in the activity network deciding project duration | RMMM = risk mitigation, monitoring and management plan
- Software Quality Assurance | SQA ensures processes and products meet standards. | SQA = planned activities ensuring software quality | ISO 9001 = quality management standard applied to software | CMM = capability maturity model with five process maturity levels
- Maintenance & Re-engineering | Most lifetime cost is spent after delivery. | Corrective Maintenance = fixing defects found after delivery | Adaptive Maintenance = changing software for a new environment | Reverse Engineering = recovering design from existing code

@ cs404 | CS-404 | Computer Organization & Architecture | CPU organisation, instruction sets, control unit, arithmetic, memory hierarchy, I/O and pipelining.
# Basic Computer Organisation
- Von Neumann Architecture & Functional Units | A computer has CPU, memory and I/O linked by buses. | Von Neumann Architecture = program and data share the same memory | Stored Program Concept = instructions held in memory and fetched for execution | System Bus = address, data and control lines connecting units
- Registers & Register Transfer | Registers hold data inside the CPU and move via micro-operations. | Program Counter = holds address of the next instruction | Register Transfer Language = notation such as R2 ← R1 for micro-operations | Accumulator = register holding one operand and the ALU result
- Instruction Cycle | Each instruction is fetched, decoded and executed. | Fetch Cycle = instruction read from memory into the instruction register | Decode = control unit interprets the opcode | Execute = operation performed and results stored
- Bus Organisation | Shared buses connect registers and memory. | Common Bus = shared path selected by multiplexers | Bus Arbitration = deciding which master controls the bus | Tri-state Buffer = gate with high-impedance state used on shared buses
# Instruction Set & Control Unit
- Instruction Formats | Instructions encode an opcode and operand fields. | Three-address Instruction = specifies two sources and a destination | Zero-address Instruction = stack-based instruction with implicit operands | Opcode = field specifying the operation
- Addressing Modes | Modes specify how the operand address is found. | Immediate Mode = operand is part of the instruction | Indirect Mode = instruction holds address of the operand's address | Indexed Mode = effective address = base + index register
- RISC vs CISC | Two design philosophies for instruction sets. | RISC = few simple fixed-length instructions; load-store design | CISC = many complex variable-length instructions | Load-Store Architecture = only load and store access memory
- Hardwired vs Microprogrammed Control | The control unit generates control signals. | Hardwired Control = control signals produced by fixed logic; fast | Microprogrammed Control = signals stored as microinstructions in control memory | Control Word = bit pattern specifying micro-operations for one step
# Computer Arithmetic
- Addition & Subtraction of Signed Numbers | ALUs use 2's complement arithmetic. | Signed Magnitude = sign bit plus magnitude | Overflow Detection = carry into and out of the sign bit differ | Ripple Carry Adder = chain of full adders passing carry serially
- Booth's Multiplication | Booth's algorithm multiplies signed numbers efficiently. | Booth's Algorithm = examines bit pairs Q0 and Q−1 to add, subtract or shift | Arithmetic Shift Right = shift preserving the sign bit | Bit-pair Recoding = modified Booth halving the number of partial products
- Division Algorithms | Hardware division uses repeated subtraction and shifting. | Restoring Division = restore remainder when subtraction gives a negative result | Non-restoring Division = skip restore and add back in the next step | Divide Overflow = quotient too large for the register
- Floating Point Representation | Real numbers are stored with sign, exponent and mantissa. | IEEE 754 Single Precision = 1 sign, 8 exponent, 23 mantissa bits | Biased Exponent = stored exponent plus bias, 127 for single precision | Normalisation = shifting mantissa so the leading bit is 1
# Memory Organisation
- Memory Hierarchy | Faster memory is smaller and costlier per bit. | Memory Hierarchy = registers, cache, main memory, secondary storage | Locality of Reference = programs reuse recently used or nearby data | Access Time = time to read or write a memory word
- Cache Memory & Mapping | Cache holds frequently used blocks close to the CPU. | Direct Mapping = each block maps to exactly one cache line | Set-Associative Mapping = block maps to any line within a set | Hit Ratio = hits divided by total memory accesses
- Main Memory & Associative Memory | RAM types and content-addressable memory serve different needs. | SRAM = static RAM using flip-flops; fast, used for cache | DRAM = dynamic RAM using capacitors; needs refresh | Associative Memory = searched by content rather than address
- Virtual Memory | Virtual memory gives programs an address space larger than RAM. | Paging = memory divided into fixed-size pages and frames | Page Fault = referenced page is not in main memory | TLB = translation look-aside buffer caching page table entries
# I/O Organisation & Parallel Processing
- I/O Interface & Modes of Transfer | The CPU communicates with peripherals through interfaces. | Programmed I/O = CPU repeatedly polls device status | Interrupt-driven I/O = device interrupts CPU when ready | I/O Port = register through which the CPU exchanges data with a device
- DMA & I/O Processors | Bulk transfers bypass the CPU. | DMA = direct memory access transfers blocks between device and memory | Cycle Stealing = DMA takes the bus for one cycle at a time | I/O Processor = dedicated processor handling I/O operations
- Pipelining | Overlapping instruction stages increases throughput. | Instruction Pipeline = stages such as fetch, decode, execute and write-back overlap | Pipeline Speedup = ideal speedup approaches the number of stages k | Pipeline Hazard = structural, data or control conflict stalling the pipeline
- Parallel Processing & Multiprocessors | Multiple processing units work concurrently. | Flynn's Taxonomy = SISD, SIMD, MISD and MIMD classification | Vector Processor = executes one instruction on arrays of data | Cache Coherence = keeping copies of shared data consistent across caches

@ cs405 | CS-405 | Operating Systems | Processes, CPU scheduling, synchronisation, deadlocks, memory management, file systems and disk scheduling.
# OS Introduction & Processes
- Operating System Functions & Types | An OS manages hardware and provides services to programs. | Operating System = system software managing resources and providing services | Multiprogramming = several jobs in memory to keep the CPU busy | Real-time OS = guarantees response within strict deadlines
- System Calls & OS Structure | Programs request OS services through system calls. | System Call = programmatic interface to request a kernel service | Monolithic Kernel = all OS services run in kernel space | Microkernel = minimal kernel with services in user space
- Process Concept & PCB | A process is a program in execution with its own state. | Process = program in execution with code, data, stack and registers | PCB = process control block storing state, registers and scheduling info | Process States = new, ready, running, waiting and terminated
- Threads | Threads are lightweight units of execution within a process. | Thread = smallest unit of CPU scheduling sharing its process's memory | User-level Thread = managed by a library without kernel support | Context Switch = saving one process's state and loading another's
# CPU Scheduling
- Scheduling Criteria | Schedulers are judged by utilisation and waiting metrics. | Turnaround Time = completion time − arrival time | Waiting Time = turnaround time − burst time | Throughput = number of processes completed per unit time
- FCFS & SJF Scheduling | Simple policies order jobs by arrival or length. | FCFS = first come first served; suffers convoy effect | SJF = shortest job first; minimum average waiting time | SRTF = preemptive SJF choosing the shortest remaining time
- Priority & Round Robin Scheduling | Policies balance importance and fairness. | Priority Scheduling = CPU given to the highest-priority process | Aging = gradually raising priority of waiting processes to prevent starvation | Round Robin = each process gets a time quantum in cyclic order
- Multilevel Queue Scheduling | Processes are grouped into queues with different policies. | Multilevel Queue = separate ready queues for process classes | Multilevel Feedback Queue = processes move between queues based on behaviour | Dispatcher = module giving CPU control to the selected process
# Process Synchronisation & Deadlocks
- Critical Section Problem | Concurrent access to shared data must be controlled. | Race Condition = outcome depends on the order of concurrent execution | Critical Section = code segment accessing shared resources | Mutual Exclusion = only one process in its critical section at a time
- Semaphores & Classical Problems | Semaphores coordinate processes using wait and signal. | Semaphore = integer variable accessed only by atomic wait and signal | Producer-Consumer Problem = synchronising a shared bounded buffer | Dining Philosophers = classic problem illustrating deadlock and starvation
- Deadlock Characterisation | Deadlock needs four conditions at once. | Deadlock = processes wait forever for resources held by each other | Coffman Conditions = mutual exclusion, hold and wait, no preemption, circular wait | Resource Allocation Graph = graph of processes and resources showing requests and assignments
- Deadlock Avoidance, Detection & Recovery | Systems prevent, avoid or recover from deadlock. | Banker's Algorithm = grants requests only if the system stays in a safe state | Safe State = some order exists in which all processes can finish | Deadlock Recovery = terminate processes or preempt resources
# Memory Management
- Contiguous Allocation & Fragmentation | Processes occupy single blocks of memory. | First Fit = allocate the first hole that is big enough | External Fragmentation = free memory scattered in small non-contiguous holes | Compaction = shuffling memory to merge free space
- Paging & Segmentation | Non-contiguous allocation removes external fragmentation. | Paging = logical memory split into pages mapped to frames | Segmentation = memory divided by logical units such as code and stack | Internal Fragmentation = unused space inside an allocated page
- Virtual Memory & Demand Paging | Pages load only when needed. | Demand Paging = page brought in only on first reference | Effective Access Time = (1 − p) × memory access + p × page fault time | Thrashing = excessive paging that collapses CPU utilisation
- Page Replacement Algorithms | When memory is full a victim page is chosen. | FIFO Replacement = replace the oldest page; can show Belady's anomaly | LRU Replacement = replace the least recently used page | Optimal Replacement = replace the page not used for the longest future time
# File Systems & Disk Management
- File Concepts & Access Methods | Files are named collections of related data. | Sequential Access = records read in order | Direct Access = records read at any position by block number | File Attributes = name, type, size, location and protection
- Directory Structures & Allocation | Directories organise files; allocation maps blocks. | Tree-structured Directory = hierarchical directories with paths | Indexed Allocation = index block holds pointers to file blocks | Linked Allocation = each block points to the next block
- Disk Scheduling | Scheduling orders requests to reduce head movement. | SSTF = shortest seek time first | SCAN = elevator algorithm moving end to end servicing requests | C-SCAN = services in one direction and jumps back to the start
- Protection & Security | The OS controls access and defends against threats. | Access Matrix = rows domains, columns objects, entries rights | Authentication = verifying user identity, e.g. passwords | Trojan Horse = program that misuses its environment while appearing useful
