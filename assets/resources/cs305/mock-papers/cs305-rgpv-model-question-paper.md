## Answer Hints (Set A)

- **Q1(a):** Object: instance of a class with state and behaviour
- **Q1(b):** Encapsulation: wrapping data and functions into a single unit | Access Specifier: private, protected or public visibility control | Getter and Setter: methods giving controlled access to private fields
- **Q2(a):** Multiple Inheritance: class derived from more than one base class
- **Q2(b):** Diamond Problem: ambiguity when two parents share a base class | Virtual Base Class: ensures only one copy of the shared base | Constructor Order: base constructors run before derived constructors
- **Q3(a):** vtable: table of virtual function pointers kept per class
- **Q3(b):** Pure Virtual Function: virtual function declared = 0 with no body | Abstract Class: class with at least one pure virtual function; cannot be instantiated | Interface: class containing only abstract methods, defining a contract
- **Q4(a):** JVM: Java virtual machine executing platform-independent bytecode
- **Q4(b):** try Block: code that may throw an exception | catch Block: handler that receives a thrown exception | finally or Cleanup: code that always runs, e.g. to release resources
- **Q5(a):** OOD: design defining classes, interfaces and collaborations
- **Q5(b):** Class Diagram: shows classes, attributes, methods and associations | Multiplicity: number of instances participating in an association, e.g. 1..* | Generalisation: UML arrow showing inheritance
- **Q6(a):** this Pointer: implicit pointer to the object invoking a member function
- **Q6(b):** Object: instance of a class with state and behaviour | Class: blueprint defining attributes and methods | Procedural Programming: program organised as functions acting on shared data
- **Q7(a):** Function Overloading: multiple functions sharing a name with different signatures
- **Q7(b):** Operator Overloading: giving an operator a meaning for class objects | Unary Operator Overload: operator function with no explicit argument as a member | Non-overloadable Operators: scope ::, member access ., sizeof and ?:
- **Q8(a):** Multiplicity: number of instances participating in an association, e.g. 1..*
- **Q8(b):** Use Case Diagram: actors and the services the system provides | Sequence Diagram: ordered message exchange between objects over time | State Chart Diagram: states of an object and transitions between them
