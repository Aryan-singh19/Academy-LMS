## Answer Hints (Set A)

- **Q1(a):** SoC: processor, memory, peripherals and accelerators on one chip
- **Q1(b):** System Specification: functional and performance requirements | Architecture Exploration: evaluating alternatives | Integration: combining IP blocks
- **Q2(a):** Router: forwards flits between links
- **Q2(b):** Memory Controller: interfaces with DRAM | Cache Coherent Interconnect: keeps caches consistent | DMA Controller: transfers data without CPU
- **Q3(a):** SystemC: C++ library for system modelling
- **Q3(b):** Pareto Front: optimal trade-off points | Performance Model: estimates throughput | Power-Performance-Area: PPA trade-offs
- **Q4(a):** Secure Boot: verifies firmware signatures
- **Q4(b):** Bare-metal: software without operating system | Device Driver: software controlling hardware | Memory-mapped I/O: registers accessed as memory
- **Q5(a):** Hardware-in-the-loop: real hardware in test loop
- **Q5(b):** Power Management Unit: controls domains | Power States: active, idle and sleep | Wake-up Sources: events that resume system
- **Q6(a):** DSP Core: signal processing engine
- **Q6(b):** SoC: processor, memory, peripherals and accelerators on one chip | IP Core: reusable design block | Platform-based Design: reuse of a common architecture
- **Q7(a):** HW/SW Partitioning: assigning functions to hardware or software
- **Q7(b):** HLS: generates RTL from C/C++ | Loop Unrolling: parallelises loops in hardware | Pipelining Pragma: directs HLS pipelining
- **Q8(a):** Power States: active, idle and sleep
- **Q8(b):** Automotive SoC: ADAS and infotainment chips | ISO 26262: automotive functional safety standard | IoT SoC: low-power connected device chip
