## Unit 4: Software Testing

### Short answer (2-3 marks)

- **Q.** Define *Verification*.  
  **Ans.** are we building the product right
- **Q.** Define *Validation*.  
  **Ans.** are we building the right product
- **Q.** Define *Test Case*.  
  **Ans.** inputs, steps and expected result for checking a feature
- **Q.** Define *Cyclomatic Complexity*.  
  **Ans.** V(G) = E − N + 2; number of independent paths
- **Q.** Define *Basis Path Testing*.  
  **Ans.** tests covering each independent path
- **Q.** Define *Statement Coverage*.  
  **Ans.** every statement executed at least once
- **Q.** Define *Equivalence Partitioning*.  
  **Ans.** divide inputs into classes expected to behave alike
- **Q.** Define *Boundary Value Analysis*.  
  **Ans.** test at and around the edges of input ranges
- **Q.** Define *Cause-Effect Graphing*.  
  **Ans.** derive tests from logical relationships of inputs and outputs
- **Q.** Define *Unit Testing*.  
  **Ans.** testing individual modules in isolation
- **Q.** Define *Integration Testing*.  
  **Ans.** testing interfaces between combined modules
- **Q.** Define *Regression Testing*.  
  **Ans.** re-running tests after changes to catch new defects

### Long answer (7 marks)

- **Q.** Explain *Testing Fundamentals* in detail with a neat diagram.  
  **Key points:** Testing finds defects before users do. Verification — are we building the product right; Validation — are we building the right product; Test Case — inputs, steps and expected result for checking a feature.
- **Q.** Explain *White-box Testing* in detail with a neat diagram.  
  **Key points:** Tests derived from internal code structure. Cyclomatic Complexity — V(G) = E − N + 2; number of independent paths; Basis Path Testing — tests covering each independent path; Statement Coverage — every statement executed at least once.
- **Q.** Explain *Black-box Testing* in detail with a neat diagram.  
  **Key points:** Tests derived from specifications without seeing code. Equivalence Partitioning — divide inputs into classes expected to behave alike; Boundary Value Analysis — test at and around the edges of input ranges; Cause-Effect Graphing — derive tests from logical relationships of inputs and outputs.
- **Q.** Explain *Levels of Testing* in detail with a neat diagram.  
  **Key points:** Testing proceeds from units to the whole system. Unit Testing — testing individual modules in isolation; Integration Testing — testing interfaces between combined modules; Regression Testing — re-running tests after changes to catch new defects.
